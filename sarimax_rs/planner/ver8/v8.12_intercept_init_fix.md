# V8.12 — Intercept (Trend) 초기값 버그 수정

## 문제 요약

`start_params.rs`의 `compute_start_params()`에서 trend 파라미터(intercept, drift)가
항상 `0.0`으로 초기화됨. `d=0, trend='c'`인 비차분 모델에서 optimizer가 올바른 basin에
도달하지 못해 지역 최솟값에 갇히는 현상 발생.

## 재현 조건

- `d=0` (비차분) + `trend='c'` (intercept 포함)
- 원 시계열의 평균이 0과 크게 다른 경우 (예: peakload ~70,000 MW)
- 계절 모델(SARIMA/SARIMAX)에서 특히 심함

## 증상

| 모델 | rs intercept | sm intercept | rs LL | sm LL | 승자 |
|------|-------------|-------------|-------|-------|------|
| SARIMA(1,0,1)(1,0,1)[7] | 1.82 | 74,563 | -22,611 | -22,421 | sm |
| SARIMA(1,0,1)(1,0,1)[24] | -0.11 | 953 | -6,643 | -5,917 | sm |
| SARIMAX(1,0,1)(1,0,1)[24]+ta | 0.0002 | -51.72 | -6,655 | -6,191 | sm |

`d≥1`인 모델에서는 차분 후 평균 ≈ 0이므로 초기값 0.0이 적절하여 문제 없음.

## 근본 원인

```rust
// start_params.rs:581-582
let kt = config.trend.k_trend();
let mut params = vec![0.0; kt];   // ← intercept = 0.0 고정
```

L-BFGS optimizer는 gradient 기반이므로 초기점이 올바른 basin에 없으면
전역 최적(intercept ≈ 70,000)까지 도달하지 못함.

## 수정 내용

차분된 시계열의 sample mean을 intercept 초기값으로 사용:

```rust
let kt = config.trend.k_trend();
let mut params = vec![0.0; kt];
if kt > 0 {
    let mean = diffed.iter().sum::<f64>() / diffed.len() as f64;
    params[0] = mean;  // intercept ← sample mean
}
```

- `d=0`: `diffed == endog` → `mean ≈ 70,000` (올바른 초기값)
- `d=1`: `diffed = Δy` → `mean ≈ 0` (기존과 동일)
- `trend='ct'`: `params[0] = mean` (intercept), `params[1] = 0.0` (drift, 이미 적절)

## 영향 범위

- `src/start_params.rs`: `compute_start_params()` 함수 1곳
- 기존 `d≥1` 모델: 변경 없음 (차분 후 mean ≈ 0)
- `d=0` 모델: intercept 초기값 개선 → 수렴 품질 향상
